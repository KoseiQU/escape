# エリア2「下水道」構造モック 4案（P5a）

DESIGN.md §3「迷路複雑度の数値基準／通路のバラエティ」と §4「P5 エリア2『下水道』」に対する
俯瞰モック。**構造だけ**（通路網・水路・段差・区画）で、ロッカー・メモ・板・音の罠・センサー・
照明・什器は P5b 以降の領分。メインが1案を選び、その `rows` をそのまま `js/maps/area2.js` の土台にする。

| ファイル | 中身 |
|---|---|
| `mockA.js` / `mockB.js` / `mockC.js` / `mockD.js` | `ESCAPE.Maps.register({ id:'area2', ... })` の完全な定義（`audit/map-mocks/mockZ4.js` と同じ IIFE） |
| `mockA.png` 〜 `mockD.png` | 1マス=6px の俯瞰図（`png.js` が出力。ブラウザ不使用） |
| `stats.js` | 統計ツール。`node audit/map-mocks-a2/stats.js audit/map-mocks-a2/mockA.js`（`--json` で JSON、複数ファイル可）。P5b-A の area2.js 検証にもそのまま使える |
| `png.js` | Node の zlib だけで PNG を書く俯瞰図エンコーダ。`node audit/map-mocks-a2/png.js audit/map-mocks-a2/mock*.js` |

凡例: `#` 壁 ／ `F` 岩盤・崩落した煉瓦の山・ポンプ等の実体 ／ `.` 歩廊・坑道 ／
`W` 水路（歩行可・足音は水・移動 ×0.75）／ `V` 深水（渡れない。legend は WALL 扱い、後で専用タイル）／
`D` 水門（出口の扉）／ `X` 到達パッド ／ `G` 水門の操作ハンドル置き場（壁マス）／ `P` セーブ端末（壁マス）。
`P` と `G` は構造モックでは `GIMMICK`（solid）に割り当ててある。

PNG の色: 壁=黒 ／ 岩盤=濃灰 ／ 床=区画色（A煉瓦 B灰 C緑灰 D橙灰 E茶 F水色灰）／ W=青緑 ／
V=濃い青緑 ／ ランプ=縞 ／ −2m の窪地=一段暗く ／ spawn=白丸 ／ exit=黄 ／ ハンドル=赤 ／
セーブ端末=紫 ／ 幹線ランドマーク=外周の細い線。

## 4案の狙い

**案A「環状幹線」** — 外周寄りを幅3の幹線水路が大きな環で回り、環から内側へ放射状の支線水路が8本伸びる。
同心の岩盤リング2枚で「外周リム／幹線の環＋沈殿帯／旧坑帯＋中央核」の3層に分け、さらに南北の放射壁で
東西を断つ。環を横切る部分は深水 `V` なので**対岸の歩廊が見えているのに渡れない**。東西を繋ぐのは中央核
（ポンプ室のある機関区画）だけ。障壁の穴は必ず2箇所・10〜20マス離す（＝2択）。
**迷い方**: 「環をどっち回りに、どこまで回るか」を繰り返し迫られる。

**案B「格子水路」** — 幹線が横3本×縦3本の格子を組み、交点9箇所が7×7の合流槽。格子が切り出す16ブロックの
中身が支線迷路。幹線の10区間を深水 `V` で分断してあり、格子は「見えているのに通れない」欠けた盤面になる。
**迷い方**: 大きな格子で方角は掴めるのに、欠けた辺のせいで素直に進めず、ブロック内の迷路へ潜っては合流槽へ出る。

**案C「二重螺旋」** — 幹線が外から中心へ渦を巻いて降りる（第一腕 → 第二腕 → 中心核）。第一腕は外周帯へしか
開かないので、内側へ入るには渦を最後まで辿るしかない。第二腕が中帯（出口のある帯）と内帯へ開く。渦の終端は
**幅3のランプ**でそのまま −2m のポンプ室へ降りる。出口は渦の反対側＝中帯の南東。
**迷い方**: 手がかりは「どこまで巻いたか」だけ。腕と腕の間の帯が支線迷路の抜け道。

**案D「蛇行本管」** — 南北に1本の本管が5回蛇行し、西岸と東岸が櫛状に噛み合う。東西の岸を結ぶのは本管の
渡渉点（`W`）と数本の暗渠だけ。岸はそれぞれ5本の岩盤帯で南北に断たれ、各帯の穴は2箇所。
中央の淀みがポンプ室（−2m）。
**迷い方**: 「川のどちら側か」「いくつ目の蛇行か」で位置を掴む。対岸が見えても渡れず、渡渉点まで岸を歩かされる。

## 比較所見

**案A「環状幹線」**
- 長所: 環＋放射支線という一目で分かる骨格があり、「環のどこにいるか」で自己位置が立つ。区画A〜Fが同心の層に
  きれいに割れるので、区画ごとの色味・音・素材の切り替えがそのまま「深く潜った感」になる。
- 長所: 独立サイクル数が最多クラス（1298）で逃げ道が濃い。幅3の幹線は片側を崩落で塞いでも必ず水路側へ逃げられる。
- 短所: 同心構造ゆえに「今どの層か」が分かりやすすぎて、迷宮としては4案でいちばん親切。spawn→ハンドルが130マスと
  近く、ハンドルの「奥へ取りに行く」感は他案より弱い（往復比は満たしている）。

**案B「格子水路」**
- 長所: 深水 `V` で欠けた格子という見せ場が強烈で、「向こう岸が見えるのに行けない」が18箇所と最多。下水道らしさも最高。
- 長所: 合流槽（広間）が9つあり、見せ場ルームと戦闘（P5e の敵）の舞台を作りやすい。最大周回路240マスと逃げ回れる。
- 短所: 格子は方角が掴みやすい反面「どの辻か」の区別がつきにくく、DESIGN §3⑥「似た見た目の交差点が連続しない」を
  満たすには区画ごとの作り分けを他案より強くやる必要がある。区画Aが293マスと小さくチュートリアル領域が狭い。

**案C「二重螺旋」**
- 長所: spawn→exit 最短 282 マスで契約幅のほぼ上限、別解成立率も最高（94.3%）。渦を辿らされる強制力が最も強く、
  「降りていく」体験が構造そのものから出る。渦の終端が幅3のランプでそのまま −2m のポンプ室に落ちるのは4案で唯一。
- 長所: 外周帯 → 第一腕 → 第二腕 → 中帯 と、進むほど風景が変わる一本道の骨格があり、物語の段取りを置きやすい。
- 短所: 機関区画（D）が92マスと小さく、中心核の見せ場が狭い。渦の外周帯（区画A）が1294マスと肥大していて、
  序盤に「広いだけの帯」を歩かせる危険がある。腕の間の帯が広く、腕を見失うと一気に迷子になる（良し悪し）。

**案D「蛇行本管」**
- 長所: 「川の右岸か左岸か」という理解しやすい軸が1本あり、迷っても本管に出れば立て直せる。最大周回路274マスで最長、
  追われたときの逃げ回りが最も気持ちよく設計できる。直線見通し最大14と最も締まっている。
- 長所: 渡渉点でしか対岸へ渡れないので、P5e で敵を入れたときの「対岸に敵がいる」緊張が作りやすい。
- 短所: 水門区画（F）が84マスと極端に小さく、終盤の水門・制御室まわりを広げる手当てが要る。
  幹線区画（B）が1388マスと過半を占め、区画の色分けの効きが他案より弱い。

### 推奨度

1. **C 二重螺旋** — 最短経路282・別解94.3%・「渦を降りる」体験と中心核への幅3ランプ。エリア1の帯構造と最も遠い迷い方。
   （手当て: 中心核を広げ、外周帯に見せ場を足す）
2. **B 格子水路** — 下水道らしさと「見えるのに渡れない」の演出力が最高。合流槽が見せ場ルームの器になる。
   （手当て: 辻ごとの作り分け、区画Aの拡張）
3. **D 蛇行本管** — 自己位置の立ちやすさと逃走の気持ちよさ。堅実だが構造の意外性は小さい。
   （手当て: 水門区画の拡張）
4. **A 環状幹線** — 骨格は最も読みやすいが、その分いちばん迷わない。チュートリアル寄りのエリアなら最適。

## 既知の妥協点

- **ハンドル（`keySafe`）の区画**: 契約は「旧坑区画Eの奥」。往復比 1.35〜1.6 を満たす袋小路が計画どおりの旧坑帯に
  無かった案（A・C）では、**ハンドルの置かれた袋小路を含む 13×13 を区画E（`old_dead` / 旧坑道の枝坑）として
  region に足してある**。結果としてどの案もハンドルは区画Eに属する（B・D は計画どおりの旧坑区画に収まった）が、A では南のリム、C では中心核の際が旧坑扱いになる。
  P5b-A で area2.js に載せる際、採用案の旧坑区画の形は手で整えること。
- **行き止まりの数**: 12〜40 の下限寄り（16〜18）。生成は「行き止まりを全部潰してループ化 → 意味のある数だけ作り直す」
  方式のため。DESIGN §3③「全てに来た意味を置く」を満たす配置物（メモ・ロッカー・セーブ端末）は P5b-A の領分なので、
  そこで必要なら数を増やす。
- **見せ場ルームは4室ぶんの矩形しか置いていない**（流入縦坑・沈殿槽・旧坑道の崩落部・水門と制御室＋ポンプ室）。
  契約の「4〜6室」は満たすが、部屋の中の作り込み（什器・タンク・梯子）は P5c。
- **区画のマス数が案ごとに大きく偏る**（例: C の A=1294 と D=92、D の F=84）。銘板アトラスは A〜F のまま使えるが、
  採用後に region の切り方を調整したほうがよい。
- **`V`（深水）の置き方**: 案B以外は「歩行可能マス同士を隔てる壁ブロックを深水に置き換える」自動配置なので、
  水路とつながって見える位置ばかりではない。採用案では水面が幹線と連続して見える位置へ手で寄せること。
- **直線見通しの上限**: ランドマーク幹線は2本ずつだが、最長はA16／B20／C17／D14 とばらついている（契約は最長20）。
- **`stats.js` の「最大周回路」は概算**（spawn からの BFS 木の基本サイクルの最大長）。真の最長閉路ではない。
- **セーブ端末 `P` は6基を機械的に散らしただけ**（P4.14 の「奥優先」方式の再現は P5b-A）。
